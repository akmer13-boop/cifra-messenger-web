# CIFRA Messenger Web v22 — RBAC + MFA

Готовая статическая WEB‑версия для Amvera Browser (Node.js 22). Версия
собрана поверх рабочей v21: лендинг, двухпанельный desktop‑режим, мобильная
навигация, темы, чаты и прежние интерактивные функции сохранены.

Добавлено по APK `CIFRA Messenger Android 2.2.0 RBAC/MFA Ready` и контракту
вложенного CIFRA Gateway:

- реальный двухэтапный вход `login → MFA challenge → session`;
- роли `Сотрудник`, `Администратор`, новая роль `Модератор`;
- назначение роли администратором в карточке сотрудника;
- обязательная MFA для `admin` и `security_moderator`;
- серверный контекст роли без возможности повысить себе права в production;
- режим аудита для администратора и модератора;
- read‑only карточка сотрудника для модератора;
- refresh/logout, единый формат ошибок API и сохранение сессии в пределах
  вкладки браузера;
- обязательная смена временного пароля, когда Gateway возвращает
  `must_change_password`;
- загрузка корпоративного каталога и серверные операции изменения профиля,
  роли и отключения сотрудника;
- runtime‑конфигурация, позволяющая переключить готовую статическую сборку с
  demo на локальный бэкенд без изменения исходников.

## Матрица доступа

| Роль WEB | Роль Gateway | MFA | Возможности |
|---|---|---:|---|
| Сотрудник | `employee` | нет | свои чаты, каталог, звонки и настройки |
| Администратор | `admin` | да | сотрудники, роли, настройки, аудит и compliance |
| Модератор | `security_moderator` | да | аудит/compliance и просмотр; без изменения сотрудников и ролей |

Проверка в интерфейсе нужна только для UX. Окончательное решение всегда
принимает Gateway по access token и ресурсной политике.

## Быстрый запуск

Требуется Node.js `22.13+`.

```bash
npm ci
npm run dev
```

Откройте `http://localhost:3000`.

Полная проверка:

```bash
npm run check
```

## Demo‑режим

Файл `public/cifra-runtime-config.json` изначально содержит `"mode": "demo"`,
поэтому ZIP сразу работает после загрузки в Amvera.

- любой непустой пароль;
- код MFA: `111111`;
- логин с `moderator` выбирает роль модератора;
- логин с `employee` выбирает роль сотрудника;
- остальные логины открываются как администратор;
- в профиле доступен демонстрационный переключатель всех трёх ролей.

Demo не является защитой и не должен использоваться для корпоративных данных.

## Подключение локального Gateway

Замените содержимое `public/cifra-runtime-config.json`:

```json
{
  "mode": "backend",
  "apiBaseUrl": "",
  "requestTimeoutMs": 15000,
  "demoMfaCode": ""
}
```

Пустой `apiBaseUrl` означает same‑origin: WEB обращается к `/api/v1/...`, а
локальный reverse proxy направляет запросы в CIFRA Gateway. Это рекомендуемый
вариант: он исключает CORS и mixed content.

Точная инструкция находится в:

- `BACKEND_INTEGRATION_RU.md`;
- `POSSIBLE_ERRORS_RU.md`.

## Развёртывание в Amvera

1. Создайте приложение с окружением **Node → Browser 22**.
2. Загрузите ZIP целиком в **Code**. Файлы уже лежат в корне архива.
3. Запустите полную пересборку.
4. Amvera выполнит `npm ci`, затем `npm run build`.
5. `amvera.yml` отдаст содержимое статической папки `out`.
6. Проверьте `/health.json`.

Отдельный `containerPort`, команда `start` и Node‑сервер не нужны. В проекте
нет Tailwind и зависимости `@tailwindcss/postcss`; `postcss.config.mjs`
намеренно пустой, поэтому прежняя ошибка Turbopack устранена.

Если Amvera должна обращаться к локальному серверу компании, браузер
пользователя обязан видеть корпоративный DNS/IP через офисную сеть или VPN.
Облачный frontend не может сам «пробиться» в закрытую LAN.

## Основные файлы интеграции

- `app/cifra-api.ts` — типизированный клиент реального Gateway;
- `app/auth-policy.mjs` — единая матрица ролей и permissions;
- `app/page.tsx` — сохранённый интерфейс с подключённым auth/RBAC;
- `public/cifra-runtime-config.json` — активный runtime‑режим;
- `public/cifra-runtime-config.backend.example.json` — production‑пример;
- `tests/rbac-mfa-integration.test.mjs` — контрактные проверки MFA/RBAC.

Архив не содержит `node_modules`, `.next`, `out`, секреты или заполненные
переменные окружения.
